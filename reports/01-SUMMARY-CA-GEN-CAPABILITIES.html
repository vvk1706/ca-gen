CA Gen Capabilities — IBM Bob

Summary of how IBM Bob handles CA Gen artefacts, what it relies on, and what its boundaries are. Includes the original user question verbatim.

User question
"Do you use any of proprietary CA Gen models or runtimes or anything else when dealing with CA Gen capabilities?"
Short answer: No — no proprietary CA Gen tooling, models, runtimes, or SDKs are used.

What IBM Bob Actually Does with CA Gen Artefacts

Everything Bob does with CA Gen material is based on reading and reasoning over the source files present in the workspace. No external tooling, runtime, or proprietary model is invoked at any point.

File types read directly

  • Generated COBOL source — .cbl
  • COBOL copybooks — .cpy
  • DB2 DDL — .sql
  • BMS screen maps — .bms
  • JCL procedures — .jcl, .proc
  • CICS resource definitions — .csd
  • Documentation and comparison files — .md, .txt

How analysis is performed

  • COBOL programs are parsed with general code-reading and reasoning — the same approach used for any COBOL source, CA Gen–generated or hand-written.
  • CA Gen–specific conventions (action diagram patterns, IEF/Advantage Gen generated COBOL structure, encyclopaedia export formats) are understood from training knowledge about the toolset — not from a live CA Gen connection.
  • All output (OpenAPI specs, data models, business rules, workflow docs) is produced by reasoning over the visible source files, not by invoking any generator.

What IBM Bob Does Not Have Access To

Item Available? Notes
CA Gen encyclopaedia / repository ✗ No The encyclopaedia database is not accessible
CA Gen Generator runtime ✗ No Cannot regenerate code or run generation steps
IEF / Advantage Gen SDK ✗ No No SDK or API calls to CA Gen tooling
Connection to CA / Broadcom tooling ✗ No No live integration with any CA product
Proprietary CA Gen parser or model ✗ No Parsing is general COBOL/SQL/text reasoning
Entity-relationship diagrams (encyclopaedia-only) ✗ No Only visible if exported to a readable file format
Action diagram logic (not exported) ✗ No Only accessible via generated COBOL in the workspace

Boundary Condition — What This Means in Practice

The analysis is only as good as what is visible in the exported source files. If CA Gen metadata lives exclusively inside the encyclopaedia — entity-relationship diagrams, unexported action diagram logic, data model relationships — Bob cannot see it unless it has been exported to a readable format first (e.g. generated COBOL, SQL DDL, or a text/markdown export).

Implication for CA Gen projects

  • Generated COBOL + copybooks + DDL give full coverage of data structures, business logic, and database operations.
  • BMS maps give full coverage of screen layouts and field names.
  • JCL and CSD give coverage of deployment and CICS resource configuration.
  • Encyclopaedia-only artefacts (diagrams, model metadata, cross-references not reflected in generated code) are outside scope unless exported.

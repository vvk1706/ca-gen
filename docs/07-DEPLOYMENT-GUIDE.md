## 3. CA Gen Generation Steps

### 3.1 Database Generation

1. Open the **Design Toolset** in CA Gen.
2. Navigate to **Database Design → Generate DDL**.
3. Select target database platform: `DB2` (mainframe) or `DB2 LUW` / `Oracle` (distributed).
4. Generate DDL for all 7 entities.
5. Review and execute the DDL on the target database:

```sql
-- Tables generated by CA Gen DDL
CREATE TABLE CANDIDATE ( ... );
CREATE TABLE LICENSE_APPLICATION ( ... );
CREATE TABLE DRIVING_HISTORY ( ... );
CREATE TABLE PAYMENT ( ... );
CREATE TABLE ISSUED_LICENSE ( ... );
CREATE TABLE AUTHORITY_USER ( ... );
CREATE TABLE LICENSE_FEE_SCHEDULE ( ... );

-- Referential integrity
ALTER TABLE LICENSE_APPLICATION ADD FOREIGN KEY (CANDIDATE_ID)
  REFERENCES CANDIDATE (CANDIDATE_ID);
-- (remaining FK constraints generated automatically)
```

### 3.2 Application Generation

1. Open the **Construction Workbench**.
2. Select **Generate → Application**.
3. Choose generation target:
   - `CICS/COBOL` for mainframe deployment
   - `Java/JSP` for web deployment
4. Select all procedures and screens.
5. Run generation — CA Gen produces source code modules.

### 3.3 Mainframe Compilation (CICS/COBOL)

```jcl
//DLISCOMP JOB 'DLIS-COMPILE',CLASS=A,MSGCLASS=X
//*----------------------------------------------------
//* Compile generated COBOL modules

//COBOL.SYSIN DD DSN=DLIS.GEN.COBOL(DLISCAND),DISP=SHR
//LKED.SYSLMOD DD DSN=DLIS.LOAD(DLISCAND),DISP=SHR
```

## 4. Reference Data Setup

Before the application can be used, reference data must be loaded:

### 4.1 Authority Users
At minimum, two authority users must exist — one at level 1 and one at level 2 — from **different authorities**.

```sql
INSERT INTO AUTHORITY_USER VALUES
  (1, 'AUTH1A', 'John Smith',   'Traffic Department',  '1', 'Licensing Div', NULL, NULL, 'A', 'LPO'),
  (2, 'AUTH2A', 'Mary Johnson', 'Road Safety Authority','2', 'Compliance',    NULL, NULL, 'A', 'LPO');
```

### 4.2 Fee Schedule
A fee schedule entry is required per license type before any payment can be processed.

```sql
INSERT INTO LICENSE_FEE_SCHEDULE VALUES
  (1, 'L', 'IF', 35.00,  '2024-01-01', NULL, 'USD', 'Learner License Issue Fee',    'A'),
  (2, 'P', 'IF', 55.00,  '2024-01-01', NULL, 'USD', 'Probation License Issue Fee',  'A'),
  (3, 'O', 'IF', 75.00,  '2024-01-01', NULL, 'USD', 'Open License Issue Fee',       'A');
```

## 5. Security Configuration

### User Roles Recommended

| Role | Screens | Description |
|---|---|---|
| `DLIS-CLERK` | SCR-CANDIDATE-MAINT, SCR-APPLICATION-ENTRY, SCR-PAYMENT-ENTRY | Front-line counter officer |
| `DLIS-CHECKER` | SCR-ELIGIBILITY-CHECK, SCR-HISTORY-CHECK | Back-office checker |
| `DLIS-AUTH1` | SCR-APPROVAL-AUTH1 | First authority approver |
| `DLIS-AUTH2` | SCR-APPROVAL-AUTH2 | Second authority approver |
| `DLIS-ISSUE` | SCR-LICENSE-ISSUE | License issuance officer |
| `DLIS-INQUIRY` | SCR-APPLICATION-STATUS | Read-only inquiry access |
| `DLIS-ADMIN` | All screens | System administrator |

### Segregation of Duties Controls
- No single user should hold both `DLIS-AUTH1` and `DLIS-AUTH2` roles.
- `DLIS-AUTH1` and `DLIS-AUTH2` users must belong to different `AUTHORITY-NAME` values in the `AUTHORITY-USER` table.

## 6. Testing Checklist

### Happy Path Test — Learner License

```
1. Create candidate: DOB at least 16 years ago
2. Create application: LICENSE-TYPE = 'L'
3. Run eligibility check → expect PASS
4. Run history check (no adverse history) → expect PASS
5. Process payment → expect receipt generated
6. Submit Auth-1 approval → expect status A2
7. Submit Auth-2 approval (different authority) → expect status AP
8. Issue license → expect LICENSE-NUMBER and EXPIRY-DATE
```

### Negative Test Cases

| Test | Expected Result |
|---|---|
| Candidate age < 16 for Learner | Eligibility FAIL: age error |
| Apply for Probation without Learner | Eligibility FAIL: upgrade path error |
| Active suspension on file | History FAIL: suspension error |
| Demerit points > 12 | History FAIL: demerit threshold |
| Unpaid fine on file | History FAIL: unpaid fines |
| Process payment twice | Error: already paid |
| Auth-1 and Auth-2 same authority | Error: segregation violation |
| Issue license before Auth-2 | Error: not fully approved |
| Invalid vehicle class | Error: invalid vehicle class |
